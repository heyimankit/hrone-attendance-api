# REVIEW.md

Comprehensive code review of starter `app/main.py` (helpers and endpoints), detailing verified defects, concrete reproduction steps, and implemented fixes.

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |

| 1 | Global setup (lines 22–24) | No database indexes created at startup; `MongoClient` initialized without `tz_aware=True`. | Race conditions allow duplicate `emp_code` and duplicate `(emp_code, date)` attendance records; PyMongo returns naive datetimes that lead to timezone comparison bugs. | Added `init_db()` in FastAPI `lifespan` creating idempotent unique and compound indexes (`uniq_emp_code`, `uniq_att_emp_date`, etc.); initialized `MongoClient(..., tz_aware=True)`. |
| 2 | `compute_late_minutes` (lines 33–37) | (a) Replaces UTC hour/minute with IST shift times; (b) Fails on overnight shifts starting on previous day; (c) Compares `minutes > 10` on floored integer instead of strictly elapsed > 10:00 (600s). | Punching in at 09:40:01 IST for a 09:30 shift has elapsed 601s -> `int(601/60) = 10`. `10 > 10` is False, returning 0 late minutes instead of 10. | Localized punch-in to IST, anchored `shift_start` to the attendance date, computed elapsed seconds, returned 0 if `<= 600`, else `elapsed_seconds // 60`. |

| 4 | `compute_overtime` (lines 44–47) | (a) Omits 30-minute minimum threshold; (b) Puts shift end on current date for overnight shifts; (c) Subtracts offset-aware datetime from naive datetime. | Punching out 5 minutes after shift end awarded 5 minutes overtime instead of 0; subtracting dates raised `TypeError: can't subtract offset-naive and offset-aware datetimes`. | Anchored shift end to next calendar day for overnight shifts, localized to IST, returned `minutes if minutes >= 30 else 0`. |

### Examined Behavior That is Not Defective
- **Synchronous FastAPI Handlers**: Using synchronous handler functions `def ...` rather than `async def` is correct when using PyMongo's synchronous client. FastAPI automatically dispatches standard synchronous functions to an external thread pool, preventing blocking of the asynchronous event loop.
- **Loading `.env` with `override=False`**: Using `load_dotenv(override=False)` allows convenient local development defaults while guaranteeing that real environment variables passed by test runners or deployment containers take precedence.
